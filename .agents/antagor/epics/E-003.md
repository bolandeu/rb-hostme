## Problem

The e2e tests import hostme.providers directly and assume Webinoly is already installed. The CLI grammar (_translate_argv), guards, exit codes and --json output are untested end to end, and the first path a new user walks — server add, server init, deploy, SSL — is not tested from zero at all.

## Goal

The paths a foreign project walks — deploy, PHP site, server add, server init, SSL — are covered by tests that call the hostme CLI itself, on a real server, and pass.

## Acceptance (Given–When–Then)

- Given a prepared test server, When the e2e suite runs, Then the smoke test drives the hostme CLI in a subprocess, not the providers.
- Given a folder with a .php file, When it is deployed through the CLI, Then the URL returns the PHP output, not the source text.
- Given a clean VPS, When server add and server init run through the CLI, Then a deployed site answers over HTTPS.

## Out of scope

- No product code change: if the CLI is broken, that becomes its own task from the report.
- No CI wiring for the e2e: it stays opt-in by env vars.
