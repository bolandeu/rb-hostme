## Problem

Two fresh-machine defects. A clean tool install pulls typer 0.29 and the CLI dies on import, so hostme 0.6.x does not start at all. On a fresh Ubuntu 26.04 VPS the Webinoly tarball download truncates, weby still prints success, and the server is left without nginx, php or the webinoly command.

## Goal

A fresh machine gets a working hostme: the CLI starts right after a tool install, and a server init that half-installed Webinoly fails loudly instead of reporting success.

## Acceptance (Given–When–Then)

- Given a clean tool environment, When the built wheel is installed, Then hostme --help exits 0 and typer resolves below 0.29.
- Given a VPS where the Webinoly tarball download truncates, When server init runs, Then it fails with a message that says the install is incomplete, and the site is never reported as ready.

## Implementation decisions

- The typer requirement carries an upper bound, so a resolver cannot pick a release the code does not support.
- Install verification is a post-condition of the Webinoly install step: the provider checks for nginx, php and the webinoly command, and raises ProviderError when they are missing.

## Test seams

- hostme.server_init over the public CLI: the verification surfaces as a non-zero exit and an error message.

## Out of scope

- Porting the code to the typer 0.29 option API: the pin fixes today, the port is its own decision.
- Finding why one VPS truncates the tarball: the network cause stays outside the product.
- Changing what Webinoly itself does to a server.
