## Problem

The type of a site is fixed when the site is created. A site that must start running PHP has no supported way to change it: Webinoly refuses to create over an existing site, so the only path is remove-and-recreate done by hand. That loses the content tree, the placeholder index and the per-site nginx extras, and it takes the site down while the operator walks the sequence. On 2026-11-12 the sysadmin hit exactly this on a live site with a certificate.

## Goal

One command flips a live site between HTML and PHP. The content stays, the certificate stays, the site comes back up on the same URLs, and the operator does not touch the server by hand.

## Acceptance (Given–When–Then)

- Given a live HTML site with content and a certificate, When the type is switched to PHP, Then the same URL returns PHP output and the content is byte-identical to before. [check: manual]
- Given a live PHP site with content and a certificate, When the type is switched to HTML, Then the site answers with the same HTML content and the certificate fingerprint is unchanged. [check: manual]
- Given a site that already has the requested type, When the switch runs, Then it changes nothing and says so. [check: manual]

## Implementation decisions

- The flag goes on the existing per-domain config command, not a new command: the operator already reads and writes site settings there.
- Verification is the post-condition, not the installer: after the switch the site must answer over HTTPS with the new type, and the content tree must be identical to the snapshot taken before the switch.
- A failed switch restores the previous type and content, and reports the failure; a half-switched site is not left behind.
- The certificate is kept: the site removal runs without revocation and the certificate is re-attached from the one that already exists.

## Test seams

- The per-domain config command over the public CLI, with its JSON report showing the site type.

## Out of scope

- Changing the type of a target deploy (ftp, sftp, plain ssh): the type belongs to Webinoly sites only.
- Moving a site to another server.
- Deciding the type at deploy time from the folder contents: that stays as it is.
