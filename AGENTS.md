# AGENTS.md

Инструкции для AI-агентов (Claude Code и т.п.), работающих в этом репозитории.

## Что это за проект

`hostme` — личный аналог surge.sh: CLI на Python/uv, который деплоит статические сайты и простые PHP-скрипты на собственные VPS (через [Webinoly](https://webinoly.com/)) одной командой, с поддержкой нескольких серверов и доменов. Полная спецификация — **[PRD.md](PRD.md)**, читай его первым для любой содержательной работы над проектом.

## Проверенные на практике факты (не гадать, не перепроверять с нуля)

Всё ниже подтверждено реальным прогоном на тестовом сервере `sites-first-beget` (Ubuntu 24.04.4, Webinoly 1.21.2, стек 1.13) 2026-09-08:

- Установка: `wget -qO weby qrok.es/wy && sudo bash weby -php` — ставит nginx+php-fpm без MySQL, проходит полностью автоматически (никаких интерактивных вопросов на этом шаге не было).
- Webroot сайта: **`/var/www/<domain>/htdocs`** (владелец `www-data:www-data`, права `750`).
- Создание сайта: `sudo site <domain> -html` (статика) / `-php`. Работает без вопросов.
- SSL на конкретный домен: `sudo site <domain> -ssl=on` — тоже полностью автоматически (HTTP-01, без ручных шагов), авто-продлевается.
- **SFTP-доступ для www-data**: актуальный флаг — **`sudo webinoly -sftp=on`**. Флаг `-login-www-data=on` из официальной документации (дамп 2024 года) на версии 1.21.2 **не работает** (`[ERROR] Please, enter a valid option!`) — используй `-sftp=on`.
- **Wildcard SSL** (`-ssl=on -wildcard`) требует DNS-01, полностью ручной и **строго последовательный** процесс (не одновременный): certbot просит одну TXT-запись → `Enter` → сразу проверяет → показывает вторую TXT-запись → `Enter` → проверяет → готово. Подробности и грабли — в `WILDCARD-SSL.md`.
- **Добавление домена к уже существующему wildcard-сертификату** — без всякого DNS: `sudo site <sub>.<base> -ssl=on -add-to-wildcard=<base>`. Проверено на двух поддоменах, сработало мгновенно, без единого ручного шага.
- Удаление сайта: `sudo site <domain> -delete=force -revoke=on` — подтверждено вживую (`tests/e2e/test_webinoly_smoke.py`).
- **Права на файлы после заливки**: SSH-пользователь на сервере — `root`, поэтому любой rsync/`tee`/`cp` пишет файлы от root. После `webinoly -sftp=on` `htdocs` создаётся с правами `750` без доступа «остальным» — root-овые файлы там **не читаются nginx** (работает от `www-data`), сайт отдаёт 403 на реально существующий контент. Обязательный шаг после заливки: `chown -R www-data:www-data /var/www/<domain>/htdocs` (или `rsync --chown=www-data:www-data`). Без этого шага `deploy` будет выглядеть успешным, но сайт не откроется.
- DNS Beget: у домена **шесть** неймсерверов тремя кластерами (`ns1/ns2.beget.ru`, `.pro`, `.com`), синхронизируются не мгновенно. При любой проверке DNS-пропагации (не только для wildcard) — проверять каждый NS отдельно (`dig ... @ns1.beget.ru` и т.д.), не полагаться на локальный/публичный резолвер (8.8.8.8 и т.п. может отдать закэшированный ответ и создать ложное впечатление, что всё разошлось).
- Тестовый сервер: SSH-алиас **`sites-first-beget`** (в `~/.ssh/config`, ключ `~/.ssh/bolandau`), реальный домен **`antagorapp.ru`** с уже настроенным wildcard DNS (`*.antagorapp.ru` → сервер) и выпущенным wildcard SSL-сертификатом (истекает 2026-12-07, продление — см. `WILDCARD-SSL.md`).

## Тестирование (обязательно)

- Покрытие **юнит-тестами обязательно** для любого нового кода в `src/hostme/`. Порог зафиксирован в `pyproject.toml` (`[tool.coverage.report] fail_under = 80`) и проверяется автоматически при каждом `uv run pytest` (через `addopts = "--cov=hostme ..."`). Не понижать порог, чтобы протащить недотестированный код — вместо этого дописывать тесты.
- **E2E-тесты обязательны** для любого поведения, которое реально трогает сервер (создание/удаление сайта, SSL, заливка файлов и т.п.) — не только юнит-моки. Живут в `tests/e2e/`, помечены `@pytest.mark.e2e` (или модульным `pytestmark = pytest.mark.e2e`), по умолчанию скипаются (см. `tests/conftest.py`) и включаются явно:
  ```
  HOSTME_E2E_HOST=sites-first-beget HOSTME_E2E_BASE_DOMAIN=antagorapp.ru uv run pytest -m e2e
  ```
- `tests/e2e/test_webinoly_smoke.py` — референсный e2e-тест полного цикла (создать сайт → SSL → залить контент → проверить `curl` → удалить). Как только появится `hostme <path> <domain>`/`hostme <domain> teardown` (TODO.md, 1.6–1.7), переписать эти тесты на вызов самого CLI вместо сырого SSH — сырой SSH был нужен только пока команд ещё не существовало.
- Гонять `uv run pytest` (юнит + покрытие) обязательно перед каждым коммитом с кодом. E2E — как минимум перед коммитом, который меняет что-то в SSH/Webinoly-слое (`hostme/ssh.py`, `hostme/webinoly.py`) — юнит-тесты с моками не ловят реальные особенности вроде прав на файлы (см. пример ниже).
- Не удалять/не упрощать e2e-тест, если он словил реальный баг (как в примере с правами `www-data` ниже) — это единственный способ поймать подобное до продакшна.

## Безопасность / что нельзя коммитить

- `vps.txt` в корне репозитория — черновик с учётными данными сервера. **Никогда не коммитить**, добавить в `.gitignore` при первом `git init` (репозиторий пока не инициализирован — см. TODO.md Phase 0).
- `~/.config/hostme/*.yaml` (реестр серверов/сайтов, будущее состояние инструмента) — вне репозитория по дизайну (PRD §8), туда не заглядывать при коммитах.
- Реальный root-пароль от `sites-first-beget` был в `vps.txt` и уже заменён на доступ по SSH-ключу — не пытаться восстановить/угадать старый пароль, он не нужен.
- API-ключи (например, попытка авторизации в Beget API) — если появятся рабочие креды, хранить вне репозитория, не в `docs/`.

- Технологии зафиксированы в PRD §8: Python + uv (`uv python pin`), Typer, `ruamel.yaml`, `rich`, SSH/rsync через `subprocess` (не через paramiko/fabric — уважать `~/.ssh/config`).
- Название проекта и CLI-команды — **`hostme`** (не Swell — было переименовано в процессе, все упоминания в репозитории уже актуализированы).
- Форма CLI-команд копирует surge.sh (`hostme <path> <domain>`, `hostme <domain> teardown` и т.п.) — не изобретать свой стиль команд, сверяться с `docs/surge-cli.md`.
