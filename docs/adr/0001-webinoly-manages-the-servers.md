# Webinoly управляет серверами

Свой сервер, свой демон и свои nginx-конфиги hostme не пишет: на VPS стоит
готовый стек Webinoly (nginx + php-fpm + certbot) со своим CLI (`site`, `stack`,
`httpauth`), и hostme вызывает его по SSH.

Причина: заводить сайт, выпускать SSL, вешать Basic Auth и держать несколько
сайтов на одной машине Webinoly уже умеет. Своя реализация того же дала бы
второй источник правды на сервере и второй набор багов.

Следствия:

- Источник правды о наличии сайта на сервере — Webinoly; локальный реестр
  описывает «что куда задеплоено».
- Установка идёт в режиме `-php` (nginx + php-fpm, без MySQL): WordPress и
  MariaDB не нужны.
- Сайты изолирует модель Webinoly (nginx server blocks, php-fpm пулы), не
  контейнеры.
- Команды `auth`, `config`, `debug`, `revs`, `rollfore` — Webinoly-специфичны,
  поэтому на target'ах (сторонних хостингах) их нет.
