# Секреты: что хранится локально, а что нет

Локально hostme держит только пути и факты, не сами секреты: `servers.yaml`
хранит путь к SSH-ключу, реестр сайтов — факт Basic Auth и логин без пароля,
пароль target'а приходит из окружения или OS keychain. Пароль Basic Auth
принимается открытым текстом в аргументе `hostme <domain> auth --pass P`.

Причина: файлы реестра человек читает и правит руками, они попадают в бэкапы,
и пароль в них живёт дольше, чем нужно. Аргумент CLI для Basic Auth принят
(2026-09-09) как достаточный компромисс: машина личная, сервер свой,
`--password-file` или stdin добавили бы шаг к каждому вызову, а выигрыш мал.

Рассмотренные варианты пароля Basic Auth: файл (`--password-file`) — отвергнут
как лишний шаг; stdin — отвергнут: его нельзя дать агенту одной командой без
пайпа.

Принятые риски:

- `--pass` в аргументе виден в `ps aux` и обычно попадает в `sudo`-лог самого
  сервера. Общее свойство передачи секрета через аргумент, не особенность
  hostme; сервер личный.
- Пароль уходит на сервер в команде `httpauth`. Проверено вживую: ошибки
  `httpauth` не возвращают креды в вывод или исключение, а аргумент
  экранируется `shlex.quote` от command injection.

Следствия: ротация пароля Basic Auth — только повторный `auth --pass`;
`hostme auth status` проверяет, что доступ есть, и не печатает значений.
