# `rsync --delete`: сервер — зеркало локальной папки

Деплой заливает файлы `rsync --delete`: содержимое webroot на сервере
становится точным зеркалом локальной папки на момент деплоя, включая удаления.
Флагом `--delete` не отключается.

Причина: повторный деплой той же папки всегда приводит сервер к одному и тому
же состоянию — без накопления мусора от старых файлов. Идемпотентность деплоя
важнее риска (hostme личный, папку выбирает человек, а не случайный скрипт).

Рассмотренные варианты: заливка без `--delete` (проигрывает: на сервере копятся
файлы, которых в папке уже нет, и сайт расходится с тем, что человек видит
локально), выключение флагом (проигрывает: два поведения деплоя вместо одного).

Следствия:

- Деплой не той (пустой, неверной) папки сносит содержимое сайта на сервере.
- Старая версия не теряется: сайт живёт в `releases/<метка>/`, а `htdocs` —
  симлинк на текущий релиз. Отсюда `rollback` и `rollfore`.
- Проверка коллизий домена (`check_collision`) защищает от записи в чужой
  сайт: домен, занятый другим локальным путём, деплой отклоняет.
