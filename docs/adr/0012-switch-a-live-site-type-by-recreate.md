# Сменять тип живого сайта пересозданием, а не правкой nginx

Webinoly не меняет тип сайта на месте: html → php требует удалить сайт и создать заново с флагом `-php`. Удаление уносит весь каталог `/var/www/<domain>` — контент, релизы, заглушку, сниппеты CORS и свой nginx-сниппет; сертификат остаётся только при `-revoke=off`. Поэтому `hostme <domain> config --php` / `--html` снимает копию каталога сайта рядом (`/var/www/<domain>.hostme-type-backup`), удаляет сайт без отзыва сертификата, создаёт с новым типом, возвращает копию, привязывает прежний сертификат и проверяет постусловие. Любой сбой возвращает прежний тип и содержимое, а снимок остаётся на сервере для ручного разбора.

Выбрали пересоздание, а не ручную правку конфига сайта: конфиг генерирует Webinoly, и `webinoly -update` его перезаписывает. Сайт недоступен между удалением и проверкой, поэтому смена проходит только с `--confirm`.

Код — `switch_site_type` в `src/hostme/providers/webinoly.py`, форма команд — `docs/usage/webinoly.md`.
