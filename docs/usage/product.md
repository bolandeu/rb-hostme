# Что такое hostme

hostme — личный аналог [surge.sh](https://surge.sh/). Одна команда берёт папку с
сайтом и делает её доступной по URL на своём VPS:
`hostme . my-landing.example.dev`.

Принципы продукта:

- **Один пользователь.** Нет регистрации, тарифов и биллинга. Всё, что surge
  продаёт в платных тарифах, здесь есть сразу: инфраструктура своя.
- **Своя инфраструктура.** Сайты живут на личных VPS с Webinoly, не в чужом
  облаке. Серверов может быть несколько.
- **Только CLI.** Веб-интерфейса нет.
- **Два вида пользователей, один интерфейс.** Человек в терминале и агент
  (Claude Code и подобные), который публикует артефакт от имени человека. Для
  агента вывод машиночитаемый, коды возврата предсказуемые, вопросов нет — см.
  [agent-contract.md](agent-contract.md).

## Что умеет

- Деплой статических сайтов и простых PHP-скриптов. Тип сайта hostme
  определяет сам: есть `*.php` в папке — PHP, иначе статика.
- Несколько серверов с Webinoly и несколько служебных (base) доменов.
- Собственные домены 2-го уровня.
- SSL (Let's Encrypt) включён всегда, отключить нельзя.
- HTTP Basic Auth, CORS, редиректы, свой nginx-сниппет.
- Релизы на сервере: `revs`, `rollback`, `rollfore`, `maintenance`.
- Заливка файлов на сторонние хостинги — target'ы (ftp/sftp/ssh).
- Машиночитаемый вывод `--json` и предсказуемые коды возврата.

Полный справочник команд с примерами печатает `hostme help`. Список команд
здесь не повторяется: docstring команды — единственный источник её формы.

## Чего hostme не делает

- **WordPress и MySQL/MariaDB.** Webinoly умеет `-wp`, но он не нужен. Если
  PHP-скрипту нужна база — SQLite внутри скрипта, без отдельного сервиса.
- **Account-команды surge** (`login`, `whoami`, `plan`, `card`, `mfa`,
  `tokens`, `invite`, `revoke`, `stats`, `nuke`): они про SaaS с чужими
  пользователями и биллингом.
- **DNS у регистратора.** A/CNAME-запись человек ставит сам; hostme DNS не
  администрирует.
- **Контейнерная изоляция.** Сайты изолирует Webinoly (nginx server blocks и
  php-fpm пулы), Docker не используется.
- **Файловый watch и автодеплой при сохранении.**
- **Свой SSL-сертификат вместо Let's Encrypt** — идея HOSTME-IDEA-005.
- **Автоматизация wildcard SSL внутри hostme** — идея HOSTME-IDEA-006.
- **git push-to-deploy и CI-интеграция** — идея HOSTME-IDEA-007.
- **`-proxy=` сайты** (reverse proxy на Node и подобное) — идея
  HOSTME-IDEA-008.
