# Безопасность

Правила, которые hostme держит, и принятые риски. Ревью секьюрити пройдено
2026-09-09; правила ниже — его итог.

## Права на файлы

- `~/.config/hostme/` и `user_data_dir("hostme")` — `700`.
- `servers.yaml`, `sites.yaml` — `600`. hostme ставит права сам при записи.

## Что hostme не хранит

- **Сам SSH-ключ.** `servers.yaml` хранит путь к ключу (`ssh_key`), файл ключа
  остаётся у ssh.
- **Пароль Basic Auth.** В реестре лежит только факт защиты и логин. Значение
  уходит на сервер при вызове и живёт только там.
- **Пароль target'а.** Приходит из окружения или OS keychain
  ([config-and-state.md](config-and-state.md)), не из `servers.yaml`.

## Что hostme экранирует

Аргумент, который уходит на сервер, экранируется `shlex.quote` — команда
`auth --pass` не может стать command injection. Проверено вживую: ошибки
`httpauth` не возвращают креды в вывод или исключение.

Ни в коде, ни в выводе нет логирования сырых команд и голых стектрейсов наружу:
ошибка приходит человеку текстом, агенту — конвертом с кодом и `action`.

## Принятые риски

- **Пароль в аргументе CLI.** `hostme <domain> auth --pass P` виден в `ps aux` и
  обычно попадает в `sudo`-лог самого сервера. Принято: машина личная, сервер
  свой, а `--password-file` потребовал бы лишнего шага у каждого вызова. Почему
  так — ADR [0005](../adr/0005-secret-handling.md).
- **`rsync --delete`.** Ошибка в пути папки сносит содержимое сайта на сервере.
  Принято ради идемпотентности деплоя — ADR
  [0006](../adr/0006-rsync-delete-mirrors-the-server.md).

## Репозиторий

`hostme` ничего не коммитит за человека и не читает реестр из репозитория.
Реестр и состояние живут вне репозитория по дизайну — ADR
[0003](../adr/0003-settings-and-state-outside-the-repository.md). Секреты в
`docs/` не попадают: ключи и пароли хранятся вне репозитория, а гейт перед
коммитом ищет их отдельным шагом.
