# Wildcard SSL для base-домена

Сертификат на `<домен>` + `*.<домен>` одним запросом. Let's Encrypt для wildcard требует DNS-01: TXT-запись `_acme-challenge.<домен>` добавляется руками в панели регистратора. Поэтому шаг ручной, `hostme` его не делает (идея HOSTME-IDEA-006). Пройдено вживую на `antagorapp.ru` и `bolandau.ru`; проверка NS и история первых грабель — `docs/research/2026-09-08-wildcard-ssl-dns.md`.

Дальше поддомены к этому сертификату цепляются без DNS-шага: `sudo site <sub>.<домен> -ssl=on -add-to-wildcard=<домен>` (решение — ADR 0009).

## Шаги

1. Зайти на сервер: `ssh <сервер>`.
2. Создать сайт-заглушку base-домена, если его ещё нет: `sudo site <домен> -html`. SSL Webinoly привязывает к существующему сайту.
3. Один раз задать email для Let's Encrypt, чтобы certbot не спрашивал его на каждом запросе: `sudo webinoly -email=<адрес>`.
4. Запросить сертификат: `sudo site <домен> -ssl=on -wildcard`.
5. Certbot печатает первую TXT-запись `_acme-challenge.<домен>` и ждёт `Enter`. Добавить её в панели регистратора (Beget: DNS-настройки домена; если панель сама достраивает домен, имя — просто `_acme-challenge`).
6. Дождаться, пока запись разойдётся по **всем** NS регистратора, и только тогда нажать `Enter`. Проверять каждый NS напрямую: `dig TXT _acme-challenge.<домен> @ns1.beget.ru` (и так все шесть). Публичные резолверы (8.8.8.8, 1.1.1.1) не годятся: они кэшируют один ответ и не показывают разнобой между NS.
7. После первого `Enter` certbot сразу проверяет первую запись без предупреждения. Если проверка прошла, он печатает вторую TXT-запись с тем же именем и другим значением. Добавить её **в дополнение** к первой (два TXT на одном имени — норма), снова дождаться всех NS, нажать `Enter` второй раз.
8. Проверить: `sudo site <домен> -info` — строка `SSL: Let's Encrypt`, SAN содержит `DNS:*.<домен>, DNS:<домен>`.

Порядок строго последовательный: две записи и два `Enter`, обе записи стоят одновременно.

## Продление

Wildcard-сертификат не продлевается автоматически: у него DNS-валидация, а Webinoly продлевает сам только обычные (`-ssl=on`). Через ~90 дней повторить шаги 4–7 (или `sudo site <домен> -ssl=force-renewal -wildcard`, всё равно с новой TXT-записью). Пропущенное продление снимает HTTPS со всех поддоменов base-домена.

## Что было не так в первый раз

Первая попытка упала с `Incorrect TXT record ... During secondary validation`: TXT-запись уже стояла в панели, но разошлась не по всем NS. Let's Encrypt проверяет из двух сетевых точек (primary и secondary), и они увидели два разных значения. Вывод — шаг 6: проверять каждый NS регистратора, а не публичный резолвер. Подробности — `docs/research/2026-09-08-wildcard-ssl-dns.md`.
